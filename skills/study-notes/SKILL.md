# 学习笔记

## 工作位置与约定

先定位用户指定的 ai-agent-book 本地仓库；此 Skill 随仓库分发，安装为软链时可解析本文件的真实位置定位仓库。若当前目录是另一个项目，不能将笔记写进该项目。

读取仓库的 [notes/README.md](../../notes/README.md)，作为目录、命名、原稿保存、Anki 导出及索引的约定。模板在 [notes/templates/](../../notes/templates/)。仅在收到相应内容时创建章节和条目，不生成虚构笔记或空白学习记录。

检查 Git 状态，优先在 `study-notes` 分支保存。当前不在该分支、且工作区干净时可切到现有 `study-notes`；存在无关改动时先确定安全存放位置，不自动 stash、丢弃改动或覆盖文件。用户已授权本仓库学习笔记整理完成后提交相关文件并推送到 `origin/study-notes`，后续本流程沿用授权；若用户当次另有指示，以当次指示为准。提交前检查范围，不夹带无关改动，不强制推送。

## 根据实际输入处理

- **思考题口述**：先将实际收到的文字逐字保存到 `notes/chapter-NN/raw/` 的独立 `.raw.txt`，原稿只含用户输入，多轮补充各存新文件。只需原始转写文字，不要求音频。用户通常只提供答案，由 Agent 从本地正文找出完整题目，不要求用户重贴。无法可靠定位的输入先存 inbox。
- **整章阅读文件**：每章全部完整题目和整理版答案合并到唯一的 `notes/chapter-NN/answers.md`，按题号排列，以完整题目为二级标题，下面直接写答案。后续补充合入同一文件，不再按单题或日期拆分整理版。使用 [答案模板](../../notes/templates/answer.md)。
- **重点摘记**：每章重点合入唯一的 `notes/chapter-NN/highlights.md`，只写标题和精炼要点；使用 [重点模板](../../notes/templates/highlights.md)。用户只让保存时保留原有表达。
- **阅读格式**：`answers.md` 和 `highlights.md` 不放记录日期、来源信息、Git 版本、原稿链接、确认状态、整理说明、待确认清单或 Agent 补充。保留正常的内容段落与小标题，不添加无待确认项等流程占位。
- **整理答案**：去掉语气词、无意义停顿和重复，重新组织论述；保留观点、条件和不确定性。按上下文最可能的含义直接修正口误与转写错误，不逐项请求确认。用户明确的自我纠正可合入答案，不把未提供的理由、例子或结论编成用户答案。
- **统一整理记录**：所有章节的转写解释、重要调整、重大歧义、原稿及附件链接、日期与正文版本、事实核对和 Agent 补充，统一写到唯一的 `notes/editing-notes.md`，按章节和题号组织；阅读文件中不出现这些记录。只记录有实质内容的说明，不添加空白或“无”条目。
- **长段自由笔记**：独立存放，不强制拆成要点；整理时保留原稿，改写内容另存。
- **手写或其他附件**：先归档实际可访问的原文件，再按需转写；不改写原图，无法辨认处标明，不假装已取得仅在聊天预览中可见但无法保存的文件。只有转写文本时明确它不是音频原件。
- **Anki**：只处理明确指定或标为 `#anki` 的内容。把适合复习的内容拆为独立问答，附来源，排除尚未确定的事实；用户观点标明“我的理解”。先存可读维护稿，再按 README 约定导出 TSV。没有制卡请求时，不把整篇笔记自动转成卡片。

默认用用户的语言，保留自然的中英混用与技术术语。章节出处从本地 `book/` 正文核对；阅读文件保存完整题目，正文 Git 版本记入整理记录。默认不先读 `book/reference-answers.md`；需要核对时，将参考意见及来源放在整理记录，不替换用户自己的答案。用户主动引用或认同参考答案的内容属于其回答，可以自然保留。

## 保存后

更新 notes 索引，直接链接整章答案和重点；确认原稿仍与实际输入一致、题目和答案齐全、两种阅读文件没有混入整理记录，所有链接有效。生成 TSV 时检查每条数据正好三列、无重复问题、没有多余表头卡片。用户提供澄清时新增原稿并更新整章整理版与集中记录，保留先前原稿。提交推送后简短告知阅读入口和结果。
