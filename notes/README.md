# 学习笔记

这里保存 Andy 的学习笔记，默认在 `study-notes` 分支维护。中文正文位于 `book/chapter1.md` 至 `book/chapter10.md`。

## 存放方式

按章节归档，实际收到内容时才创建对应目录。跨章节内容放在 `cross-chapter/`，暂时无法定位的内容放在 `inbox/`，后续确认后移动并更新链接。

```text
notes/
  chapter-01/
    highlights/       重点摘记，以 bullet points 为主
    answers/          思考题口述原稿与整理版答案
    freeform/         长段随笔、自由笔记、手写笔记的可选转写
    attachments/      原始图片、扫描件、音频等附件
    anki/             选出的复习卡片 Markdown 与导出的 TSV
  cross-chapter/
  inbox/
  templates/
```

文件使用 `YYYY-MM-DD-主题` 命名，同日同主题加 `-02` 等后缀，避免覆盖。思考题在主题前加 `q01` 等题号。例如同一次输入的 `2026-11-08-q01-context.raw.txt` 与 `2026-11-08-q01-context.answer.md` 共用文件名前缀。日期按用户时区记录，默认 Asia/Taipei。

## 重点、自由笔记与手写材料

- 重点摘记使用 [highlights.md](templates/highlights.md) 模板；每条尽量只写一个观点。书中结论、自己的想法和待解问题分别标明。
- 长段笔记可以直接存放，不强制改成 bullet points。需要整理时，先保存 `.raw.txt`，整理内容另存 `.md`，参考 [freeform.md](templates/freeform.md)。
- 手写笔记先保留原始文件，再按需创建转写稿、整理稿或卡片；原图和转写稿互相链接。无法辨认处标为 `[无法辨认]`，可能的读法放在待确认处。
- 只保存实际收到的附件；拿不到附件文件时，记录来源和“原件未归档”，不能声称已保存。

## 口述思考题的处理

1. **先保存原稿**：将收到的用户输入逐字存为 `.raw.txt`，使用 UTF-8；不加标题，不清理语气词、停顿标记、重复、中英夹杂或口误。每条后续补充单独保存，保留输入顺序。
2. **定位题目**：记录章节、题号、题目原文、正文路径及当时的 Git 提交号。优先根据用户指定位置定位；不明确时先归档到 inbox，不猜题号。保留题目原文是为了应对后续正文题号变化。
3. **整理答案**：用 [answer.md](templates/answer.md) 模板，去掉 filler words（如“嗯”“然后”）、重复和无意义停顿；修正确定的口误；按“观点—理由—例子或条件”组织，按实际内容取舍。保留原有立场、语气强弱、保留意见和中英术语。
4. **保留歧义**：可能改变观点的词句、相互矛盾的说法、缺失论据都列入“待确认”，必要时在答案中保留 `[待确认：…]`。用户明确自我纠正时可采用纠正后的说法，并记下重要修订。
5. **区分补充**：事实核对、推导、参考答案对照和 Agent 建议放在单独的补充区，附来源，不写成用户自己的观点。默认先整理用户答案，不主动拿参考答案替换。
6. **保留历史**：澄清后的答案可以修订，原稿不改；新输入单独追加为新文件，并在整理版列出全部原稿链接。

这里的“原稿”指 Agent 实际收到的文字。用户已确认：语音输入保存原始转写文本即可，不需要音频。收到整批输入时可以同时保存完整原稿和各题逐字摘出的原稿，摘录不做语言清理。

用户通常只提供答案。每份整理版必须从本地正文查出并附上完整题目，便于对照，不要求用户重贴题目。

## Anki 卡片

用户明确说“做成卡片”，或将要点标为 `#anki` 时，才把对应部分转为卡片；不把所有笔记自动制卡。

- 一张卡片只考一个可独立回答的知识点，题干包含必要上下文，答案简短、可检验。复杂思考题先保留完整答案，需要时再拆成适合复习的概念、条件或比较。
- 有歧义、未核实的事实不直接进入卡片；个人观点若用于复习，题干明确写“我的理解”，避免当成普遍结论。
- 在 `anki/<文件名前缀>.cards.md` 保存可读的问答、标签及相对来源链接；再按需导出同名前缀的 `.tsv`。Markdown 是维护稿，TSV 是导出稿，不做两个独立版本。
- 默认使用正反面问答。UTF-8 TSV 每条记录一行，三列依次为 `Front`、`Back`、`Tags`，以真实制表符分隔，不加入普通表头数据行。字段内换行用 `<br>`，正文中的 HTML 特殊字符先转义；标签用空格分隔。
- 导入时选择 Anki 的 Basic（或对应的基础问答）笔记类型，将三列映射到正面、背面和标签；使用 `<br>` 时启用字段内 HTML。卡片可带 `ai-agent-book chapter-01` 等标签，背面附来源说明，方便回看。
- 导出前检查重复问题。需要覆盖已有导出时从维护稿重新生成；修改已导入卡片的正面可能影响 Anki 的重复识别，重新导入前说明这一点。不自动连接或修改 Anki 牌组。

## 如何交给 Agent

可以使用 `$study-notes`，再说明章节和输入类型，例如：

- “用 `$study-notes` 记第一章重点，标了 #anki 的内容做成卡片：……”
- “用 `$study-notes` 整理第二章第 3 题，以下是我的口述：……”
- “用 `$study-notes` 存这份手写笔记，先保留原图，再帮我转写。”
- “把这段存为自由笔记，保留段落，不用转成要点：……”

Skill 源码保存在 [skills/study-notes/SKILL.md](../skills/study-notes/SKILL.md)。如果当前会话尚未发现它，可以直接让 Agent 读取这个文件并按流程执行。

保存到工作区后，Agent 应报告文件位置、待确认项和制卡情况。用户已授权本仓库学习笔记整理完成后，直接提交相关文件并推送到 `origin/study-notes`；后续本流程沿用此授权，除非用户另行指定。提交包含本流程需要的笔记、模板和 Skill 变更，先检查暂存范围，不夹带无关改动。远端冲突时不强制推送。
