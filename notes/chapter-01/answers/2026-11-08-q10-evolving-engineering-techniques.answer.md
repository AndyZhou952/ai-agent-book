## 题目原文

10. ★★★ 引言指出 “好的设计原则应该穿越模型的迭代周期”，但实现这些原则的具体工程手段可能会随模型能力进步而过时。试举一个这样的 Agent 工程手段，并说明理由。

## 我的答案（整理版）

### 我首先想到的例子：显式 ReAct 提示

我首先想到的是早期 ReAct 的显式提示方式：通过 prompt 要求模型先思考、输出相应的思考轨迹，再进行工具调用。当时工具调用也可能出现格式问题。

随着大量后训练，一些模型已内化了相应的推理与行动能力，因而不一定还需要用同样严格的 prompt 逐步要求它“先思考，再行动”。不过，对复杂任务，我仍认为可以通过 prompting 引导模型拆分任务。

### 我认同的参考答案例子

以下两个例子来自参考答案，我认为也符合自己的设想。

1. **要求提示词和全部工具定义必须预先放在上下文开头。** 早期模型指令遵循能力有限，提示或工具定义离开熟悉的位置后，可能难以正确识别和执行；放在轨迹中间也可能增加查找成本。Skills 在运行时按需加载提示，动态工具发现也会在找到新工具后追加定义。随着模型指令遵循能力增强，以及针对动态加载的后训练，我认为不再需要把“所有提示和工具定义都固定放在开头”作为普遍要求。
2. **通过严格的约束采样，强制工具调用符合指定格式。** 早期模型容易生成 illegal JSON 或遗漏参数，这类措施可以作为可靠性补丁；随着格式遵循能力提高，它的额外收益可能降低。

另外，外部知识库的使用方式，以及是否必须采用标准工具调用格式，也可以作为继续思考的例子。我目前只记录这些方向，尚未展开论证。
