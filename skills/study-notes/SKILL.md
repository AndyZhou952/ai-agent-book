# 学习笔记

## 工作位置与约定

先定位用户指定的 ai-agent-book 本地仓库；此 Skill 随仓库分发，安装为软链时可解析本文件的真实位置定位仓库。若当前目录是另一个项目，不能将笔记写进该项目。

读取仓库的 [notes/README.md](../../notes/README.md)，作为目录、命名、原稿保存、Anki 导出及索引的约定。模板在 [notes/templates/](../../notes/templates/)。仅在收到相应内容时创建章节和条目，不生成虚构笔记或空白学习记录。

检查 Git 状态，优先在 `study-notes` 分支保存。当前不在该分支、且工作区干净时可切到现有 `study-notes`；存在无关改动时先确定安全存放位置，不自动 stash、丢弃改动或覆盖文件。用户已授权本仓库学习笔记整理完成后提交相关文件并推送到 `origin/study-notes`，后续本流程沿用授权；若用户当次另有指示，以当次指示为准。提交前检查范围，不夹带无关改动，不强制推送。

## 根据实际输入处理

- **重点摘记**：写精炼要点，区分书中观点、用户理解、待解问题。用户只让保存时保留原有表达。
- **思考题口述**：用户已确认仅保存原始转写文字即可。先逐字保存实际收到的用户文字到独立 `.raw.txt`，再创建链接原稿的 `.answer.md`。原稿文件只含用户输入，不混入 Agent 说明；多轮补充各存新文件。用户通常只提供答案，整理版必须从正文查出并附上完整题目，不要求用户重贴。题目章节明确但题号不明时查正文，无法可靠定位则先存 inbox 并询问关键缺失信息。
- **整理答案**：去掉语气词、无意义停顿和重复，重新组织论述；保留观点、条件和不确定性。用户已授权按上下文最可能的含义直接修正口误与转写错误，不逐项请求确认；必要时在整理说明中简短记录解释。只有多个解释同样合理且会明显改变观点时才保留待确认。用户明确的自我纠正可合入答案，原始说法仍留在原稿。不把未提供的理由、例子或结论编成用户答案。
- **长段自由笔记**：独立存放，不强制拆成要点；整理时保留原稿，改写内容另存。
- **手写或其他附件**：先归档实际可访问的原文件，再按需转写；不改写原图，无法辨认处标明，不假装已取得仅在聊天预览中可见但无法保存的文件。只有转写文本时明确它不是音频原件。
- **Anki**：只处理明确指定或标为 `#anki` 的内容。把适合复习的内容拆为独立问答，附来源，排除尚未确定的事实；用户观点标明“我的理解”。先存可读维护稿，再按 README 约定导出 TSV。没有制卡请求时，不把整篇笔记自动转成卡片。

默认用用户的语言，保留自然的中英混用与技术术语。章节出处从本地 `book/` 正文核对；保存题目原文和正文 Git 版本，避免题号变化后失去对应。默认不先读 `book/reference-answers.md`；需要核对时，将参考意见放在 Agent 补充区，不替换用户自己的答案。

## 保存后

更新 notes 索引，链接主条目；确认原稿仍与实际输入一致、整理稿未将补充冒充原话，链接指向已有文件。生成 TSV 时检查每条数据正好三列、无重复问题、没有多余表头卡片。简短告知保存位置、待确认内容以及是否生成卡片。用户提供澄清时新增原稿并更新整理版，保留先前原稿。
