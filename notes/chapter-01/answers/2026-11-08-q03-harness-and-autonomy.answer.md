## 题目原文

3. ★★ “模型即 Agent” 范式意味着模型在工具调用决策上越来越自主。但本章论证了 Harness 工程的重要性反而在增加。这两个趋势如何共存？Agent 框架未来的核心价值体现在哪些方面？

## 我的答案（整理版）

并不是所有工作都需要高度灵活的工作流。有些工作需要探索、反复尝试；另一些工作有固定流程，适合由 Harness 通过 hard code 施加 constraint。

模型在工具调用决策上更自主，意味着中间过程可以减少人工细化。例如，遇到 error 时，模型可以自行判断如何处理，并独立完成一部分任务。

但对于要求严格遵循 A→B→C 的流程，我仍然倾向于用 Harness 限定执行顺序、排除其他路径。即使 Agent 自己也能完成这条流程，框架约束仍能提升安全性和稳定性。

因此，模型的自主性与 Harness 的价值可以共存：模型承担更灵活的决策，框架约束具有不确定性的输出和执行过程。我认为框架的核心价值主要体现在安全性与稳定性上。

## Agent 补充

“排除其他路径”的保证取决于约束是否覆盖全部实际执行入口，不能由模型口头承诺流程顺序来保证。正文强调执行前、上下文之外的验证机制，见[第一章护栏部分](../../../book/chapter1.md)。
